# Clean architecture / CQRS (no MediatR)

- `SharedKernel/Messaging` defines `ICommand`, `ICommand<T>`, `IQuery<T>`, and their handlers. Handlers return `Result`/`Result<T>` (`SharedKernel/Domain/Result.cs`) and don't throw for expected failures.
- Each `*.Application/DependencyInjection.cs` registers handlers by Scrutor assembly scan, then wraps them with `TryDecorate`: `ValidatingHandlers` (runs FluentValidation validators one after another and returns a `ValidationError`) inside `LoggingHandlers` (source-generated `LoggerMessage` logs), in `*.Application/Abstractions/Behaviors`. Handler methods are `HandleAsync`. A new handler is picked up automatically. A new validator only needs to exist in the assembly.
- Controllers inject the handler directly into the action method, e.g. `ICommandHandler<AddProductCommand, Guid> handler`, and map failures with `result.Error.ToActionResult()`. `Error.Code` (a `System.Net.HttpStatusCode`) is the HTTP status. Routes are versioned: `[ApiVersion(1)]`, `api/v{v:apiVersion}/...`.
- Application features are organized as vertical slices: `Application/<Aggregate>/<UseCase>/` holds the Command/Query, Handler, and Validator.
- **Data access:** handlers use `IApplicationDbContext` (`<Service>.Application/Abstractions/Data`), implemented by the service's `ApplicationDbContext`: DbSets plus `SaveChangesAsync`, written as LINQ in the handler, with `AsNoTracking` for reads. There are no repositories and no `IUnitOfWork`, except Cart's `CartRepository`, which stores carts in Redis. Identity also declares `ExecuteInTransactionAsync`, which joins a transaction that is already open (the consumer outbox's). Use it only when `ExecuteUpdate`/`ExecuteDelete` or a second save must commit together with tracked changes; one `SaveChangesAsync` is already a transaction.
- **IDs:** each entity has a strongly typed ID record created in the domain with UUIDv7 (`public static ProductId New() => new(Guid.CreateVersion7());`, called from `Create`), so the entity has its ID before it is saved. Never use `Guid.NewGuid()` for a key. References to another service's entity (`Order.UserId`, `CartItem.ProductId`, `StockReservation.OrderId`) are plain `Guid`. Commands, requests, responses, routes (`{id:guid}`) and integration events carry plain `Guid`; handlers wrap them (`new ProductId(request.Id)`). SQL Server doesn't sort `uniqueidentifier` in UUIDv7 order, so each configuration makes the Guid key nonclustered and clusters on a shadow `bigint IDENTITY` column, `ClusterId`. Order rows by `ClusterId` (`EF.Property<long>(x, "ClusterId")`), not `Id`, when you need creation order.
- **Domain rules return `Result`, they don't throw.** `Money.Add` returns `Result<Money>` (`Money.CurrencyMismatch`) and `Currency.FromCode` returns `Result<Currency>` (`Currency.Unsupported`); handlers build a `Currency` from request data with `FromCode` and return `ValidationError.Collect(...)` when it fails. `Currency.None` (the currency of `Money.Zero()`) is not a supported code, so EF value conversions read stored values back with `Currency.FromStoredCode`, which accepts it and throws on a corrupt value. A domain object can't be created invalid: `Product.Create` returns `Result<Product>` and `Product.Update` returns `Result` (`ProductErrors.InvalidPrice` for an amount <= 0, `InvalidStockQuantity` for a negative quantity, both BadRequest). Handlers return that error and seeders take `.Value`; the FluentValidators stay as the first line of defence. Throw only for bugs, invalid internal state and infrastructure. A value object that wraps a primitive must be created through a private constructor and `static Result<T> Create(...)` with a get-only `Value`; this repo has no such wrapper today (names, descriptions and emails are plain strings checked by FluentValidators), and `Currency` is the only smart enum.
- **Child collections are read-only.** `Order.OrderItems` and `Cart.CartItems` are `IReadOnlyList<T>` over a private `List<T>` field (EF maps `_orderItems` by convention) and change only through aggregate methods.
- **Domain services:** a rule goes in a domain service, not an aggregate or a handler, when it works on more than one aggregate, depends on stored data outside them (such as a pricing rule), or is a business operation no single aggregate owns. `Catalog.Domain.Products.StockReservationService` reserves and releases stock (a `Product` and its `StockReservation`s). Aggregate methods that must only run inside the service are `internal` (`Product.ReserveStock`/`ReleaseStock`), so stock can't change without a reservation record. The handler loads, passes the time, adds the new rows and saves.
- Aggregate roots derive from `AggregateRoot<TId>` and call `RecordDomainEvent`; child entities (`CartItem`, `OrderItem`, `StockReservation`) derive from `Entity<TId>` and record nothing. `ApplicationDbContext.SaveChangesAsync` collects the events with `PullDomainEvents` (through `IHasDomainEvents`) and dispatches them through `DomainEventsDispatcher` after the save succeeds, each handler in its own DI scope. Time comes from .NET's `TimeProvider` (registered as `TimeProvider.System`), not a custom clock interface. Identity uses this to mail token links (`UserTokenIssuedDomainEvent`). The DbContext also turns `DbUpdateConcurrencyException` into `ConcurrencyException`, which the API's `ExceptionHandler` (`IExceptionHandler` plus `AddProblemDetails`, in `*.API/Infrastructure`) maps to 409; any other unhandled exception becomes a 500 problem-details response. `Product`, `Order` and Identity's `RefreshToken` have `RowVersion` concurrency tokens.

## Code-level runtime behavior

- Cart rebuilds cached carts with Newtonsoft.Json (`CacheService`). Its `PrivateResolver` fills private setters and the private list fields behind read-only collections (`CartItems => _cartItems`), and `CurrencyJsonConverter` rebuilds `Currency` (private constructor, get-only `Code`) through `Currency.FromStoredCode`. Cached types still need a (private) parameterless constructor.
- Nullable warnings are on. EF Core binds an entity's real constructor when every parameter maps to a plain property (`User`, `Category`, `Order`, `OrderItem`, `RefreshToken`), so those have no parameterless constructor. Where a constructor takes an owned type or a navigation (`Product`, `UserToken`), or Newtonsoft needs one (`Cart`, `CartItem`), the private parameterless constructor is wrapped in `#pragma warning disable CS8618`. Response, request and options classes mark non-nullable strings `required`.
